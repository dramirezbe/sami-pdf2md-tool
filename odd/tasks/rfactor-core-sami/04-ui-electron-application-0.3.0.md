# 04 — Electron application depending on CLI, version 0.3.0

Date: 2026-11-18, America/Bogota. Status: specification for future implementation.
Future branch: `feat/0_3_0_sami_ui`, created from `main` after publishing CLI `0.2.0`.
Units U08–U09. Depends on [03 — published CLI](03-cli-batches-validation-release-0.2.0.md).
Next: [05 — UI deployment and release](05-ui-deployment-release-0.3.0.md).

## Stage outcome

A useful desktop application that executes the installed CLI and displays its results. Stack: Electron + JavaScript + HTML/CSS, PDF.js, and markdown-it/KaTeX. Prioritize development simplicity; do not add a component framework, HTTP server, or embedded Python backend for the first functional interface.

It does not import `sami` modules, convert PDFs, detect GPU, prepare models, or decide conversion backend compatibility. It may open files for display and perform desktop operations; all conversion/health/cancellation goes through the CLI protocol.

## U08 — CLI location, health, and execution

### Location and identity

1. Read the installation record generated by CLI bootstrap, with absolute path and `installation_id`.
2. Query that path with `health --json`. Do not use the first `sami` found in `PATH`, cwd, or the document directory.
3. Check protocol v1, supported CLI version, and ready CPU paths. The graphical manifest pins the exact tested CLI version; sharing the `0.2` prefix does not establish compatibility.
4. `ready/degraded` allow opening/working; `degraded` displays a GPU→CPU notice. If CLI is missing or the contract is incompatible, explain recovery graphically without pretending conversion is available.

Health does not load models or download. Run it once at opening and for actions that justify checking a change; not on every screen render or each added PDF. Conversion has its own health check per batch, as normal CLI does.

### Execution

The main process uses `child_process.spawn` with absolute path, argument array, `shell:false`, and `windowsHide:true`. CLI is a direct executable; do not depend on a `.cmd` or shell activation to work on Windows.

Proposed graphical request:

```text
<cli-path> convert <inputs...> --mode balanced --json --control-stdin
```

Add output/recursive/flat options only when chosen. The option/capability list matches the published CLI; do not show toggles that are ignored. Each invocation is a batch, not a process per page or message.

`cli-runner` receives stdout chunks, incrementally decodes UTF-8, and frames JSON lines. Forward v1 events to the renderer through specific methods, retaining `run_id/job_id/attempt`. stderr feeds a diagnostics panel; it does not determine percentages.

Proposed presentation state: installation/health, selected inputs, options, current execution, and terminal results. Do not duplicate deduplication, final naming, quality, or fallback rules in JS: CLI responses are authoritative.

### States and recovery

| Situation | State/UI |
|---|---|
| Waiting for health | Visible window with brief activity, without freezing presentation. |
| CLI ready | Select files and convert. |
| GPU failed, CPU ready | Informational warning; execution/cancellation remain available. |
| Invalid installation/protocol | Diagnostics view and explicit installer repair action; no secret downloads at opening. |
| Batch running | Inputs/options fixed for that batch; changes apply to the next one, not the current run. |
| Crash without `run_finished` | Graphical error with useful exit/stderr; do not mark converted or remain in progress indefinitely. |
| Partial/failed document | Show explanation and preserve other batch results. |

### Cancellation and window closure

Cancel sends the v1 command on stdin and waits for terminal result/CLI cleanup. Do not launch global `taskkill` from the renderer or manage VLM servers in JS.

If the user closes the window during work, offer cancel/close or continue with the window open. For the chosen closure behavior, request CLI cancellation and apply the supervisor timeout if unresponsive; do not exit leaving an orphan conversion process. This interaction is a UX choice, not GPU fallback, which always happens automatically.

If a child needs forced closure, limit it to the owned process/tree, following the CLI policy. Test that the app does not kill a separately launched `sami` in another terminal.

### Minimum bridge

Proposed operations: `getHealth`, `selectFiles`, `selectFolder`, `startConversion`, `cancelConversion`, `openOutputFolder`, `loadPreview`, `startResultDrag`; event/diagnostic subscriptions with unsubscribe on view closure. Do not expose `exec(command)` or the entire IPC interface to document previews.

User-selected paths or CLI-returned paths define resources the UI may preview/export. Isolate document-content views from process operations.

### U08 tests and completion

Use a test CLI emitting events, not an imported Python package: Unicode, fragmented lines, simultaneous stderr, warning, partial, crash, cancellation, and incompatible version. Test CLI paths containing spaces, launch without refreshed `PATH`, and closure with owned child/grandchild processes.

Then connect the actual published CLI: health, one-page conversion, cancellation, and preserved results. **Completion:** no duplicated conversion rules; every execution path has a visible terminal state. **Rollback:** removing UI/runner does not alter CLI installation or results.

## U09 — Screen, viewers, and drag and drop

### Minimum functional screen

| Area | Elements and behavior |
|---|---|
| Inputs | Add PDFs, add folder, drop files/folders, remove selection. Display names/paths, not full file content in the list. |
| Options | `balanced` initially selected; recursive folders, optional destination, flat. |
| Status | Summary of compatibility/effective CPU-GPU, without exposing package lists in the main flow. |
| Execution | Convert, cancel, current document/stage, document-count progress. |
| Results | Status per document, actual output paths, warnings, Open folder button. |
| Viewers | Embedded source PDF and converted Markdown, selecting the result to preview. |

Workspace is a selection/navigation preference. Output directory is separate: when not selected, **each PDF** converts beside its source as defined by CLI. Do not use the executable directory, shortcut directory, or first PDF directory as an implicit destination for the entire batch.

To avoid duplicated rules, the UI may list added folders as folders; CLI resolves actual count/order at startup and emits `inputs_resolved`. Duplicates and matching names are reflected from its result.

### Viewers

- Local PDF.js: load the selected PDF, pages, zoom, and navigation; add search if viewer integration supports it without rebuilding the viewer.
- Local markdown-it + KaTeX: Markdown and formulas, sanitized table HTML, resources relative to the final document. Do not modify the `.md` when displaying it.
- Show a graphical message if a resource is missing. Preview failure does not change CLI-reported conversion status.
- Document content cannot execute commands/scripts or navigate arbitrary system paths. External links open only through explicit user action.

Bundle libraries with styles/fonts/PDF worker. Avoid CDN dependencies so the installed UI works offline. Do not substitute the browser's built-in viewer without checking interactions and local-file handling on target operating systems.

### Drag and drop and output directory

Inbound: drag/drop events, native paths recovered with `webUtils.getPathForFile`, and standard folder selection. Do not use old `File.path` or trust paths from a fabricated web object.

Outbound: native Electron dragging of existing files, with icons and result paths. For outputs with images, offer the result directory as the main unit to preserve links; if exporting only Markdown, explain that without silently changing its references. In flat mode, export must include CLI-returned resources or use a prepared export directory; do not assume `.md` is self-contained.

The UI may copy already generated files for export: this is a presentation/file operation, not an alternative converter. Do not parse Markdown to reconstruct resources when CLI already returns their paths. Start with copying and preserve originals; moving requires a later UX decision.

Test dragging to Explorer and at least one Linux file manager in the matrix; the recipient decides accepted types. When it does not accept the exported type, Open folder allows manipulation through the OS file manager. Do not promise compatibility with literally every receiving application.

### U09 tests and completion

Flows: two PDFs and a directory, different paths, per-input default destination, shared/flat output, numbered second conversion, error/partial, CPU warning, table/equation/figure previews, reference links, inbound/outbound drag, and offline use.

Do not require professional visual polish or bundle-size optimization. Require useful controls, basic keyboard navigation, and a responsive window while CLI works. **Completion:** functional development application; final deployment/release remain in plan 05.

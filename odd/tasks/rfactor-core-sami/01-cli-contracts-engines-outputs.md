## U00 — Feasibility and baseline, before refactoring

1. Record the SHA, resolved Marker/Surya/Torch versions, and models in the reference installation. The project pins Marker `2.0.0`; do not silently upgrade it while moving functions.
2. Convert both existing PDFs with both current modes, retaining references through `--no-strip-refs`. Save results and metrics outside the source tree; define small expectations for text, figures, tables, and equations.
3. Measure the Caste batch with `high/ocr=False/images=False`, separating conversion from its later random audit. Measure startup and steady conversion separately on the same PDFs/machine.
4. Test an actual CPU path for both Marker profiles on Windows 11 and a chosen Debian/Ubuntu baseline. Confirm the server binary, dependencies, and that models can remain entirely local. The `fast` engine does not need that inference.
5. Record an `OS/architecture/driver/runtime/model/engine → tested/untested/unsupported` matrix and RAM limits. Initially propose x86_64; establish minimum versions from evidence, not the distribution name.

**Completion:** reproducible baseline and CPU feasibility evidence. If a profile cannot run on CPU on a required platform, resolve that dependency before declaring support; do not replace Marker with another converter or downgrade the mode without discussing the product change.

## U01 — Contract and preservation of Marker

### Mode table

| Public mode | Implementation | Default |
|---|---|---|
| `fast` | Caste with its internal `high` configuration, OCR and images off. | No. |
| `balanced` | SAMI/Marker with internal mode `fast`. | Yes. |
| `quality` | SAMI/Marker with internal mode `balanced`. | No. |

Move the required conversion functions and subclassing from `sami/cli.py` to the adapter. Preserve provider → document → layout → lines → highres → OCR → structure → processors → rendering order. Replace progress `print` calls with callbacks; do not change algorithms or postprocess its prose with Caste heuristics.

**Backend and device per mode are fixed by [06 — engine backend and GPU policy](06-engine-backend-and-gpu-policy.md):** `balanced` uses RF-DETR on Torch with **no** inference server; `quality` uses the VLM on local `llama.cpp` (GGUF), configured explicitly so Marker/Surya never reach for Docker/vllm. The adapter must set the llama.cpp backend and local GGUF paths before `create_model_dict()`. Do not auto-switch the public mode based on VRAM (see D3): hardware only scales the `quality` offload.

Remove the `strip_references` call from the new path. Accept `--no-strip-refs` for compatibility without changing the result. Retain figures and references generated by Marker. The bibliography/link policy and safe publication are intentional differences from the old default.

### Minimum types

| Type | Fields and rule |
|---|---|
| `ConversionRequest` | `job_id`, absolute PDF path, mode, options, staging directory, device, and `attempt`. No UI objects. |
| `EngineResult` | Markdown body, generated relative resources, processed pages, warnings, gaps, and metrics. Does not publish final files. |
| `JobResult` | Input, `mode`, effective engine/device, status, final paths, warnings/errors, duration, and attempt count. |
| `RunResult` | Totals by status, result list, and exit code. A document retried on CPU is counted only once. |
| Input error | Unreadable/encrypted/invalid PDF; not a GPU failure and does not trigger a device retry. |
| Acceleration error | Failed GPU backend/driver/VRAM/inference; enables one CPU retry in plan 02. |

Pass paths as path values or separate arguments, never as a shell command string. Adapters write exclusively to staging; publication is a shared responsibility.

### CLI protocol 1, consumable without importing Python

`sami health --json` emits **one JSON object**, without mixed logs. Conversion with `--json` emits **UTF-8 JSON Lines** on stdout; human messages and library output go to stderr. Do not send full document bodies or base64 images as events; provide result paths.

Proposed envelope:

```json
{"protocol_version":1,"event":"job_progress","seq":7,"run_id":"r1","job_id":"j1","attempt":1,"data":{"stage":"extracting","completed":2,"total":5,"unit":"pages"}}
```

| Event | Required data |
|---|---|
| `run_started` | Resolved mode/default and CLI version; stable `run_id`. |
| `inputs_resolved` | Unique document count, order, and discovery issues. |
| `job_started` | Input, index, batch total, engine/device, and attempt number. |
| `job_progress` | Stage and actual units; `total:null` when not measurable. |
| `warning` | Stable code, message, and context. `GPU_FALLBACK_CPU` includes cause and device change. |
| `job_retrying` | Previous/new device and reason; does not increment completed documents. |
| `job_finished` | One terminal `JobResult`; only one per document, after all attempts. |
| `run_finished` | Counters, duration, and exit code; exactly one on normal completion or cancellation. |

The coordinator assigns increasing `seq` values. Consumers ignore unknown additive fields/events; they reject an incompatible major version. JSONL may arrive in fragments; buffer until newline. A crash without a terminal event is a process failure, not success.

Document states: `succeeded`, `partial`, `failed`, `cancelled`; reserve `skipped` for an omission policy that is actually implemented. Removed duplicates are neither converted nor failed documents. Do not confuse warnings—for example GPU→CPU—with content loss.

For UI control, propose `--control-stdin`: it receives JSON lines such as the following; terminal Ctrl+C maps to the same cancellation mechanism. EOF on stdin does not cancel by itself.

```json
{"protocol_version":1,"command":"cancel","run_id":"r1"}
```

### U01 tests and completion

- Request, event, and result parsing/serialization; Unicode and paths containing spaces.
- Same corpus, versions, and comparable options: new Marker adapters versus U00 baseline. Review content/structure, not variable times or metadata.
- `import sami.cli`, help, and version do not download, import Torch/Marker, or register global handlers incompatible with Windows.

## U02 — Fast engine, references, and shared outputs

### Effective Caste configuration

Extract useful `Options`, normalization, layout, prose, tables, extraction, and QC from [the reference](../refactor-core-sami/PDF2MD_caste.py). Preserve its actual invocation, not its nominal `fast` preset: `high`, `ocr=False`, `images=False`, `markers=True`, `pipe` tables, and no default page limit.

Do not import the converted notebook file: it contains global execution. Do not run pip/apt, Tesseract, reactive OCR, random auditing, model detection, or downloads during conversion. Preserve its `run` consistency checks within the separated responsibilities; do not add a second heavy extraction to suggest independent verification.

For scans without text: emit a warning/gap and `partial`; do not invent content or enable OCR. Replace original `overwrite=True` with numbering, as instructed. Speed is a comparative target against U00; measure added costs for links, events, and staging.

### References inside Markdown

1. Retain all bibliography extracted by the engine; disable SAMI's own reference removal.
2. Preserve URL/DOI destinations already in the text and recoverable PDF annotations. Use inline Markdown links, never an external bibliography file.
3. In Caste, reuse extracted coordinates/spans to associate links with text. Do not blindly match globally and link the first repeated word on the page.
4. If an annotation has a URL but cannot be inserted unambiguously at its position, preserve it in a recovered-links section inside the same `.md`, with the available page/label and a warning. Do not invent a citation–bibliography relationship.
5. Represent internal destinations with anchors if the target page/section exists in the output; otherwise record the limitation. Do not query the network to complete titles or DOIs.

This policy is the permitted content adaptation in addition to preserving Marker output. UI previews do not convert or rewrite files.

### Naming and publication

| Input/destination | Expected result |
|---|---|
| `paper.pdf`, no previous output | `paper/` directory with `paper.md` and relative resources. |
| Same PDF converted again | `paper_2/paper_2.md`; then `paper_3/…`, preserving prior versions. |
| `--output out/` | Same policy under `out/`. |
| `--flat --output out/` | `out/paper.md`, then `out/paper_2.md`; resources in a unique namespace per published attempt. |
| Two PDFs with the same name in one batch | Reserve distinct names deterministically; never overwrite because their stems match. |

Reserve output identity with exclusion between SAMI processes. Stage on the destination filesystem; final commit must not replace someone else's file that appeared meanwhile. For directory output, publish a complete prepared directory. For flat output, publish unique resources first and Markdown last; on failure remove only new resources unreferenced by a published document.

Do not create an empty final directory at startup that looks like a valid conversion. Never publish a discarded GPU attempt. Do not delete or rename original PDFs. Results contain the actual final paths for CLI/UI.

### U02 tests and completion

- Caste tables and columns contain expected content; scans with OCR off finish partial without loading OCR.
- Bibliography and text/annotation links in both engines; repeated reference, ambiguous link association, and missing internal destination.
- Normal/flat output, second attempt, matching names, Unicode, and injected failure between resources and Markdown: previous output intact, cleanup limited to the current attempt.
- Compare Caste latency before/after in the same environment, excluding auditing and model startup.

**Completion:** preserved engines, verifiable v1 contract, and safe outputs. **Rollback:** remove U02 without deleting published results; a format migration never deletes documents.
